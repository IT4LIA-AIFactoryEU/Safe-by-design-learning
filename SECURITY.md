# Security policy

## Supported versions

| Version | Supported |
|---|---|
| 1.x | Yes |
| < 1.0 | No |

Only the latest release in a supported major series receives security fixes.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities through public issues, pull
requests, or discussions.

Use GitHub private vulnerability reporting when it is enabled. If that channel
is unavailable, contact `support-it4lia@cineca.it` with the subject
`GITHUB IT4LIA - Security: Safe-by-design EBM` and ask for a confidential
reporting channel. Do not include exploit code, credentials, or sensitive data
in the initial message.

Please provide the affected version, impact, reproduction conditions, and any
suggested mitigation. The maintainers target acknowledgement within five
business days and an initial triage update within ten business days. Remediation
timing depends on severity and reproducibility. Coordinated disclosure will be
agreed with the reporter.

## Scope

Reports may cover source code, dependency use, release artifacts, workflows,
or unsafe file handling. Scientific limitations, model accuracy questions, and
learned-model certificate assumptions are not security vulnerabilities and
should use the issue templates instead.
